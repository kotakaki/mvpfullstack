# Rabiloo ブログコンテンツ 棚卸し・再構築戦略 (2026版)

## 1. 戦略のパラダイムシフト

Webサイトリニューアルに伴い、ブログコンテンツの役割を以下の通り再定義します。

| 項目 | 従来 (Past) | 今後 (Future) |
| :--- | :--- | :--- |
| **サイト構造** | 汎用的な開発・DX・技術の羅列 | **① 業界・課題ソリューション軸** ＋ **② 先端AI技術・実装特化軸** |
| **ターゲット** | ITリテラシーを深めたい一般層 | **① 課題解決を探す決裁者** ＋ **② 実装の壁に直面するCTO/リードエンジニア** |
| **ブログの役割** | とにかくPVを集める（認知拡大） | **① ソリューションCVへの導線** ＋ **② AI技術力の証明とPoC・コンサルCV** |
| **コンテンツ評価** | トラフィック量（表示回数） | **ソリューション・AI開発との関連性、エンゲージメント、CV貢献度** |

## 2. 記事の仕分け基準（4つのTier）

既存の記事群を、新サイトの戦略に合わせて以下の4つのTier（階層）に仕分けます。AI技術領域は、独立した強力な武器として最上位に位置づけます。

### Tier 1: 戦略コア（KEEP & UPGRADE）
リニューアル後のサイト構造の「2つの柱」となる記事。
*   **Tier 1-A: ビジネスソリューション軸**
    *   **定義**: 業界課題の解決、DX推進に直結する記事。決裁者向け。
    *   **アクション**: 最新事例の追加、パッケージソリューションページへの強力なCTA設置。
*   **Tier 1-B: 先端AI技術・実装ノウハウ軸 (Tech Blog)**
    *   **定義**: LLM、RAG、ファインチューニング等、Rabilooの主力技術である特定のAI専門技術を深掘りした記事。CTOや開発責任者向け。
    *   **アクション**: コードの最新化、「AI開発支援・PoCコンサル」等への技術者向け特化CTAの設置。技術力の高さを証明する。

### Tier 2: トラフィックハブ・技術選定ハブ（REPURPOSE）
*   **定義**: 直接的なCVにはやや遠いが、トラフィックを集めている基礎記事や、**発注者・担当者がWebアプリ/モバイルアプリ開発の技術選定時に調べる記事**（React Native, Vue, Firebaseなど）。
*   **アクション**: 記事自体は残すが、エンジニア向けのトーンから発注者向けに調整し、Tier 1や【アプリ・システム開発サービス】のページへ送客するための「バナー/リンク設置用ハブ」として割り切る。

### Tier 3: クラスター化・再編（CLUSTER / MERGE）
*   **定義**: 「オフショア開発」など、テーマは重要だがトラフィックが分散している記事群。
*   **アクション**: すべてを1記事に物理的に統合するわけではありません。**「Pillar & Cluster（親・子記事）モデル」**へと再編します。
    1. 親となる「完全ガイド（Pillar記事）」を新設する。
    2. 検索意図が独立している優良な記事（費用相場、契約形態など）は「子記事（Cluster）」として残し、親記事と相互リンクを結ぶ。
    3. 内容が重複している薄い記事（失敗事例とリスクなど）のみ、統合して301リダイレクトを行う。

### Tier 4: 削除・パージ（DELETE / NO INDEX）
*   **定義**: 「AI以外の領域」で、トラフィックが少なく、CVに全く繋がらない陳腐化した汎用技術HowTo。
*   **アクション**: 思い切って削除（404）し、サイト全体の「AIソリューション特化」の専門性評価（E-E-A-T）を高める。

## 3. GA4データに基づく初期仕分けリスト（案）

いただいたデータを基にした、具体的な仕分けの一次案です。

### 🟢 Tier 1-A: ビジネスソリューション軸（決裁者向けCV）
*   【2025年】AIエージェントとは？生成AIとの違いをわかりやすく解説！
*   AIエンプロイー（AI社員）で24/7業務改革
*   集客アプリを作ってリピート客を増やせ！
*   クラウド型デジタルサイネージとは？多拠点運用に失敗しない仕組み
*   中小企業のDXは何から始める？進め方を実際の成功事例をもとに解説！
*   「人月商売」からの脱却｜AI時代に開発の対価を再設計するための構造論

### 🔵 Tier 1-B: 先端AI技術軸（CTO・開発責任者向けCV）
*   LLMをローカルで動かす方法：Ollamaで最小構成からスタート
*   vLLMを使ってコストゼロで実現するローカルLLMホスティング実装ガイド
*   はじめてのRAG実装ガイド｜構築フロー・主要ツール・成功のコツを解説
*   LoRA / QLoRAでLLaMA 3をファインチューニングする方法
*   GRPOによるファインチューニングでパスポートデータ抽出の精度向上
*   AWS Lambdaで実現するクラウド環境LLMデプロイ入門

### 🟡 Tier 2: トラフィックハブ（送客装置として割り切る）
B2BのCVには遠いが、認知獲得と集客を担っている記事です。ここからTier1へ流します。
*   そもそもアプリとは？お年寄りにもわかるように易しく説明します！
*   【素朴な疑問】アプリケーションとソフトウェアの違いって？
*   エンジニア1人月単価の相場とは？工数単価の内訳と見積もりの考え方を解説
*   【初心者でもわかる】クラウドサービスとは？わかりやすく解説！
*   LLMをローカルで動かす方法：Ollamaで最小構成からスタート

### 🟠 Tier 3: 統合検討（テーマをまとめる）
*   **「オフショア開発」関連の集約**
    *   「オフショア開発でよくある失敗事例と成功するための7つの対策！」、「オフショア開発に潜む4つのリスク…」などを、1つの「オフショア開発・ベンダー選定完全ガイド」に統合する。
*   **「DX基礎」関連の集約**
    *   「【図解でわかる】DXとIT化の違い…」、「デジタイゼーションとデジタライゼーションの違いは？」を統合する。

### 🔴 Tier 4: 削除・パージ対象（ノイズとなる記事）
リニューアル後の「課題解決」にそぐわず、特定エンジニアしか検索しないようなニッチな技術記事、PVが少ない記事群。
*   【Laravel mix】キャッシュされたCSS/JSファイルを自動的に強制クリア
*   Nginxによるロードバランサーでサーバーの負荷分散をする
*   Vue.jsとは？Webサイト高速化の仕組みをわかりやすく解説！
*   React Nativeのパフォーマンスを向上させる基本的な方法
*   （その他、過去の開発言語特化の細かいTips記事や、社内イベント系の記事でPVが少ないもの）

## 4. 削除（パージ）実行のメリット

不要なコンテンツを削除することで、SEO上の大きなメリットがあります。
1.  **クロールバジェットの最適化**: Googleのクローラーが、本当に順位を上げたいTier 1の重要記事を頻繁に巡回するようになる。
2.  **トピック・オーソリティの向上**: サイト内の「技術Tips」の割合が減り、「AI・DXによるビジネス課題解決」のコンテンツ比率が高まるため、Googleから「このドメインはビジネス課題解決の専門サイトである」と評価されやすくなる。
3.  **ユーザー体験（UX）の向上**: サイト内検索や回遊時に、ノイズとなる古い記事にユーザーが迷い込むのを防ぐ。
