# Qwen3とは？アリババ発LLMの特徴と、Qwen3.7まで続く進化・企業導入の判断軸を解説

「Qwen3（クウェン3）を以前調べた。でも、あれから半年以上が経って、今もその情報は使えるのか」という声を、導入支援の現場でよく耳にします。

現場で伴走していると気づくのは、「Qwen3」という検索で到達できる情報の多くが、2025年4月の初代発表時点で止まっているということです。実際には、アリババはその後わずか1年余りでQwen3.5、3.6、3.7と世代を積み上げており、組織体制・ライセンス戦略・モデルアーキテクチャのいずれも大きく様変わりしています。「中国製の安いモデル」という一括りの評価は、もはや現状に追いついていません。

この記事では、初代Qwen3の設計思想を軸に据えながら、Qwen3.7までの進化の流れ、最新のLMArena評価と競合比較、ローカル実行の現実的な要件、そして企業が導入判断をする際のリスクと判断軸を整理します。

読み終えると、以下の4点が整理されます。

- 初代Qwen3の「**ハイブリッド思考モード**」と「**MoE構造**」が実務でどう意味を持つか
- Qwen3.5〜3.7まで、モデルファミリーがどのように進化してきたか（LMArena Eloスコア比較付き）
- Qwen3.5系のローカル実行に必要なハードウェア要件の最新版（量子化別）
- 企業が中国製LLMを導入する前に確認すべき、**組織変動リスク**を含むセキュリティチェックリスト

## Qwen3とは？アリババが開発した「実務寄り」の大規模言語モデル

**Qwen3（クウェン3）とは、中国のAlibaba Cloud（アリババクラウド）が開発・公開した[大規模言語モデル](https://rabiloo.co.jp/blog/llm)（LLM）です。**

2025年4月28日の初代発表以来、わずか1年余りでQwen3.7世代まで進化を重ね、2026年6月時点では累計2億3,400万人以上のアクティブユーザーを持つエコシステムへと成長しています。

オープンウェイトで提供され、商用利用も可能。複数のモデルサイズが揃っており、ローカル環境から大規模クラウド環境まで、幅広い用途に対応できる設計になっています。

### 開発元・公開時期・ライセンスの概要

Qwen3の開発・公開の概要は以下の通りです。

| 項目 | 詳細 |

ライセンスが**Apache 2.0**である点は、企業にとって重要なポイントです。商用目的での利用・改変・再配布が認められており、自社業務への組み込みや、RAG（検索拡張生成）システムへの統合なども、追加のライセンス料なく実施できます。

ただし、Qwen3.5以降の最上位モデル（PlusおよびMaxシリーズ）については、API専用のプロプライエタリモデルとして提供される二元体制に移行しています。「ローカルで動かせるか、APIのみか」は、モデルのサイズとシリーズによって異なります。

### 「DeepSeekショック」後に登場した背景と、現在の立ち位置

Qwen3の登場を理解するには、2024年末から続く「中国発LLMの台頭」という流れを把握しておく必要があります。

当時、DeepSeekがGPT-4oに匹敵する性能を圧倒的な低コストで実現したことで、業界に衝撃が走りました。Qwen3は、その流れを受けて登場した中国発LLMのひとつです。

ただし、Qwen3はDeepSeekとは異なるアプローチを取っています。単なるコスト競争ではなく、**思考の深さを制御できるハイブリッドモード**という独自の設計思想を前面に出してきました。

## Qwen3の最大の特徴：「ハイブリッド思考モード」とその進化

多くのLLMは、どんな質問に対しても同じ処理方式で回答します。

**Qwen3が異なるのは、タスクの複雑さに応じて「考える深さ」を切り替えられる点です。**

この仕組みを「ハイブリッド思考モード」と呼びます。複雑な推論問題には時間をかけて考え、シンプルな質問には即座に答える。1つのモデルがその両方をこなします。さらにQwen3.6-Plus世代では、この「思考の深さ」を長いセッションをまたいで保持できる仕組みへと進化しています。

Qwen3には、2つの動作モードが実装されています。

| モード | 動作 | 適したタスク |
|--------|------|-------------|
| **Thinking Mode（思考モード）** | 最終回答の前に、ステップごとに推論過程を展開する | 数学・論理問題、コード生成・レビュー、複雑な分析 |
| **Non-Thinking Mode（非思考モード）** | 思考プロセスを省略し、即時に回答を返す | 日常的な質問応答、文章要約、翻訳、チャットボット |

従来のLLMでは、「深く考えるモデル」と「素早く答えるモデル」は別々に存在していました。

Qwen3はこの2つを**同一のモデル内で統一**しています。用途ごとにモデルを切り替える必要がなくなる点は、実装の観点から見ても大きな利点です。

### 「思考予算（Thinking Budget）」から「preserve_thinking」へ

Thinking Modeには、さらに細かい制御機能があります。

**「思考予算（Thinking Budget）」**と呼ばれる概念で、推論にどれだけの計算リソース（トークン数）を割り当てるかをユーザー側が指定できます。

- 予算を多く割り当てる → 深く考える、より精度の高い回答
- 予算を少なく抑える → 速く答える、コストを下げる

初代Qwen3では、このパラメータで最大**38,000トークン**までの思考プロセス長を制御できます。APIを通じて設定できるため、エンジニアが用途や優先事項に応じて柔軟に調整できます。ユーザー向けチャットボットでは速度重視、バックエンドでの複雑な処理では精度重視、といった使い分けが同一モデルで実現します。

さらに、Qwen3.6-Plus（2026年4月リリース）では、この「思考の制御」がより実用的な形へと進化しました。

**`preserve_thinking` パラメータ**を有効にすると、長時間のデバッグやマルチターンの対話においても、過去の推論ステップを一貫して保持できます。モデルが「前のターンでどう考えたか」を記憶したまま次の判断を下せるため、複雑な問題を複数のやり取りにわたって解きほぐすエージェント的な用途で効果を発揮します。同時に、冗長な思考トークンの消費も抑制できるため、長期セッションのコスト管理にも貢献します。

精度とコストのトレードオフを「モデル選択」ではなく「パラメータ設定」で制御できる点は、Qwen3ファミリー全体を通じた設計上の特徴のひとつです。

## Qwen3モデルファミリーの進化：初代から3.7世代まで

Qwen3が「大きいのに速い」を実現している背景には、アーキテクチャ上の工夫があります。

**Qwen3ファミリーの一部モデルは「MoE（Mixture of Experts）」と呼ばれる設計を採用しており、全パラメータを常時動かすのではなく、入力に応じて必要な部分だけを動的に呼び出す仕組みになっています。**

この構造を土台に、アリババはQwen3.5・3.6・3.7と世代を重ね、単なるテキスト処理モデルから「数時間にわたって自律稼働できるエージェントAI」へと急速に進化させてきました。

### MoEアーキテクチャの概念：専門家ネットワークの動的呼び出し

MoE（モー）とは、モデル内部に複数の「専門家（Expert）」ネットワークを持ち、入力されたタスクに応じてその一部だけを起動する設計です。

イメージとしては、社内に数学・コーディング・文章作成など複数の専門チームがいて、質問の内容に応じて担当チームだけが応答する形に近いです。

この構造がもたらすメリットは2つです。

- **高い推論能力**：タスクに特化したエキスパートが応答するため、汎用設計より精度が出やすい
- **高速かつ低コスト**：動かすパラメータ数を抑えられるため、実際の計算コストを削減できる

初代フラッグシップの「Qwen3-235B-A22B」を例にすると、総パラメータ数は235Bですが、推論時に実際に動くのは22B分のパラメータです。235Bの能力を持ちながら、動作コストは22B相当に抑えられています。

## Qwen3をローカルで動かす：最新スペックと現実的な手順

Qwen3を試す方法は複数ありますが、データを社内に閉じたい場合に最も手軽なのがローカル実行ツール「**Ollama**」を使う方法です。

**Ollamaを使えば、コマンド数行でQwen3のモデルウェイトをダウンロードして動かせます。**サーバーへの登録も不要で、手元のマシン上で完結します。

### Ollamaを使ったローカル起動の概要

Ollamaは、オープンウェイトLLMをMac・Windows・Linux環境で手軽に動かすためのオープンソースツールです。

インストール後、以下のコマンドでQwen3.5を起動できます。

```bash
# Qwen3.5（9Bモデル）を起動する場合
ollama run qwen3.5:9b

# 日本語タスク向けにQwen3.5（27Bモデル）を使う場合
ollama run qwen3.5:27b
```

起動後はターミナル上でそのままチャット形式で入力できます。APIとして使う場合は、Ollamaがローカルにエンドポイントを立ち上げるため、OpenAI互換のAPIクライアントからそのまま呼び出すことも可能です。

```bash
# ローカルAPIとして呼び出す例（curlで確認）
curl http://localhost:11434/api/generate \
  -d '{"model": "qwen3.5:9b", "prompt": "Qwen3とは何ですか？"}'
```

また、Alibabaが提供する公式のWebUI「**Qwen Chat**（chat.qwen.ai）」を使えば、インストールなしにブラウザ上でQwenファミリーを試すこともできます。まず動作感を確認してからローカル導入を判断する、という進め方も有効です。

### 量子化別・必要メモリの最新目安

ローカル実行に必要なハードウェアは、選ぶモデルのサイズと「量子化（Quantization）」の精度によって変わります。

量子化とは、モデルの重みを低ビット数で表現することでファイルサイズとメモリ消費を削減する技術です。精度を多少犠牲にする代わりに、より小さなメモリ環境で大型モデルを動かせるようになります。

以下は、Qwen3.5ファミリーをUnsloth Dynamic量子化で動かす際の、システム全体（VRAM＋システムRAM合計）の目安です。

| モデル | UD-Q4_K_XL（4bit） | BF16（非量子化） | 動作環境の目安 |
|--------|-------------------|----------------|-------------|
| Qwen3.5-9B | **6.5 GB** | 19 GB | 一般的なLinux PC、MacBook Air（M2以降） |
| Qwen3.5-27B | **17 GB** | 54 GB | MacBook Pro（M3 Pro）、GPUサーバー |
| Qwen3.5-35B-A3B（MoE） | **22 GB** | 70 GB | **Mac Studio（Mシリーズ・24GB以上）** |
| Qwen3.5-122B-A10B | **70 GB** | 245 GB | 高スペックGPUサーバー（A100等） |
| Qwen3.5-397B-A17B | **214 GB** | 810 GB | マルチGPU環境 |

注目すべきは「Qwen3.5-35B-A3B（MoE）」です。総パラメータ350億のモデルが、4-bit量子化により**22GBのメモリで動作**します。Mac Studio（Mシリーズ統一メモリ24GB〜）の領域に収まるため、データ保護を優先するチームがセルフホストで業務検証する際の現実的な選択肢になります。

> **注意**：上記の数値は目安です。量子化ビット数や同時実行プロセスの状況によって変動します。まずQwen3.5-9Bの4-bit版で動作確認をとり、タスクの精度要件に合わせて上位モデルへ移行するのが、リスクを抑えた進め方です。モデルの取得は[Hugging Face（Qwen公式ページ）](https://huggingface.co/Qwen)から可能です。

### 組織変動リスクをどう評価するか：Alibaba Token Hub体制への移行

データセキュリティと並んで、企業の導入担当者が見落としがちなのが「継続性のリスク」です。

**新体制の骨子：**

### 現実的な3つのリスク対策とQwen3導入前チェックリスト

リスクをゼロにはできませんが、適切な対策で許容範囲内に収めることは可能です。

**対策1：機密データにはローカル実行を原則とする**
顧客情報・未公開の設計情報・契約書などを入力する業務には、クラウドAPIを使わずローカル実行環境を整備する。「どのデータなら外部送信してよいか」を社内ルールで明文化することが先決です。

**対策3：利用規約とデータ学習設定の確認**
クラウドAPI利用の場合、入力データがモデルの再学習に使われる設定になっていないかを必ず確認してください。「設定できる」と「デフォルトでオフ」は異なります。

**Qwen3導入前チェックリスト**

- [ ] **データの機密性評価**：入力するデータは外部サーバーを経由しても問題ない情報か
- [ ] **利用形態の選定**：クラウドAPIとローカル実行のどちらが自社の用途・リスク許容度に合うか

- [ ] **社内ガイドラインの整備**：利用する従業員全員に、利用範囲とリスクを教育できているか

モデルは「1つだけを選ぶ」ものではなく、業務の種類ごとに組み合わせて使うのが現実的な構成です。たとえば、機密データを扱う業務にはQwen3.5ローカル、エージェント的な開発補助にはQwen3.7-Max API、高精度レポート生成にはClaude Fable 5、といった役割分担も十分に選択肢に入ります。

## よくある質問

**Q1. Qwen3は日本語でも精度よく使えますか？**

Qwen3.5以降は201言語・方言に対応しており、日本語の処理精度も評価されています。ただし、日本語特有の文化的ニュアンスや業界専用語については、実際の業務データで検証することを推奨します。特に法律・医療・金融など専門用語が多い領域では、まずPoC（概念実証）で精度を確認してから本番適用を判断してください。

**Q2. Qwen3.5とQwen3（初代）の違いは何ですか？**

大きく3点異なります。第一に、アーキテクチャの刷新（Gated Delta Networksを用いた線形アテンション構造の採用）により、長大なコンテキストを扱う際のメモリ効率が大幅に改善されています。第二に、対応言語が119言語から201言語に拡大されました。第三に、コンテキスト窓がQwen3.6-Plus世代で100万トークンに到達しています。基本的な「ハイブリッド思考モード」の設計思想は両世代で共通です。

**Q3. Qwen3を商用利用する際に費用はかかりますか？**

Qwen3.5などのオープンウェイトモデルはApache 2.0ライセンスで公開されており、商用利用・改変・再配布に追加のライセンス料は不要です。ただし、Qwen3.7-MaxやQwen3.7-PlusなどAPI専用の上位モデルを使う場合は、Alibaba Cloud Model StudioまたはQwen Cloudの従量課金が発生します（例：Qwen3.7-Plus 入力$0.40/1Mトークン）。ローカル実行の場合はインフラコストのみです。

**Q4. 2026年3月の幹部退社で、Qwen3の継続性は大丈夫ですか？**

アリババは幹部退社後、CEO呉泳銘直轄の「Alibaba Token Hub」という新体制を設立し、QwenをMaaS事業の中核として位置づけています。組織的には「研究プロジェクト」から「商用事業」への格上げと捉えることができます。一方で、特定のモデルへの依存リスクは常に存在します。中小型のオープンウェイトモデル（Qwen3.5系）をローカルに保持しておくことで、API提供状況の変化に左右されない運用体制を備えておくことが、現時点での現実的な対策です。

**Q5. 個人のPCやMacでQwen3.5は動きますか？**

Qwen3.5-9Bの4-bit量子化版（UD-Q4_K_XL）であれば約6.5GBのメモリで動作します。MacBook Air（M2以降・16GB）でも試せる計算です。Mac Studio（Mシリーズ・24GB統一メモリ）であれば、Qwen3.5-35B-A3B（MoE）の4-bit版（約22GB）という、より大型のモデルも動作します。まずOllamaを使って9Bモデルで動作確認をとり、タスクの精度要件に合わせて上位モデルへ移行するのが最もリスクの低い進め方です。

## まとめ：Qwen3は「試して判断する」段階から「設計に組み込む」段階へ

Qwen3ファミリーは、オープンウェイトLLMの中で実務への適応性を意識して設計されたモデルです。

初代が提示した「ハイブリッド思考モード・MoE構造・Apache 2.0・多言語対応」という4つの軸は、Qwen3.7世代においても核心として機能し続けています。そしてQwen3.7-Maxが示した「35時間・1,158回のAPIコール・10倍の高速化」という実績は、このモデルファミリーが単なるチャットAIを超えて、エージェントAIの実用水準に達したことを示しています。

現時点での現実的な進め方は、次の順序です。

1. **Qwen3.5-9Bをローカルで動かし**、自分たちの業務タスクで動作確認をとる
2. 精度が要件を満たすなら、**Qwen3.5-35B-A3B（Mac Studio 24GB対応）**へ移行する
3. 長時間の自律処理やエージェント的な用途が必要なら、**Qwen3.7-MaxのAPIとキャッシュ機能**を検証する

最終的に「どのモデルが自社の業務に合うか」は、実際に試さないとわかりません。ただ、試し方の設計を間違えると、検証コストだけがかさみます。
